# NFC 태그 덮개 제어 이식·수정 안내

## 원본에서 확인한 사항

- `.aia`의 Screen1에는 NearField 컴포넌트/태그 감지 이벤트가 없습니다.
- `Clock1.Timer`에서 블루투스 상태 문자열의 15번째 문자(`nfc_mode`)를 읽어 덮개 버튼 색을 바꿉니다.
- 원본 ZIP의 ATmega128A `main.c`에는 PN532 NFC 리더기 파싱과 두 개의 태그값(`0xA7` 열림, `0x99` 닫힘)이 이미 존재합니다.
- 원본에서는 실제 덮개 구동 코드가 `start_mode == 1` 조건 안에 있습니다.

## 수정된 파일

`firmware/ATmega128A/microchip_studio/DogFood_ATmega128A/main.c`만 기능 수정했습니다.

1. `nfc_lid_request`, `nfc_last_tag`로 태그 인식 이벤트를 단 한 번 큐잉합니다.
2. `USART1_RX_vect`의 태그 식별에서 열기/닫기 이벤트를 기록합니다.
3. `main` 루프에서 자동모드와 무관하게 해당 태그의 덮개 명령을 실행합니다.
4. `TIMER1_COMPA_vect`에서 `NFC_LID_MOVE_SECONDS`(기본 5초) 후 모터를 정지합니다.
5. 자동모드 루프의 기존 무한 덮개 구동을 제거합니다.
6. 앱 버튼 `e/f/g`와 전체 리셋 `j`는 기존대로 지원하며, NFC 타이머가 앱 명령에 간섭하지 않도록 처리합니다.

## Android Studio 코드

별도 수정하지 않았습니다. 이미 `DogFoodProtocol.kt`에서 `D` 상태 패킷의 `coverMode = part(14, 15)`를 처리하고, `MainActivity.kt`의 `styleCoverButtons`에서 열림/닫힘 상태가 반영됩니다.

## 주의 및 검증

- 하드웨어에서 5초가 안전한지 먼저 확인하세요. 타이머는 1초 단위라 실제 시작 시점에 따라 구동 시간이 약 4~5초일 수 있습니다.
- 모터 이동 끝을 확실히 감지하려면 리미트 스위치/전류 제한 등의 하드웨어 안전 조치가 필요합니다.
- 테스트 시 사료·물과 기구부 하중을 제거하고 모터 전원 분리 상태부터 태그 상태 인식을 확인하세요.
- `0xA7`, `0x99`는 원본 펌웨어가 **4바이트 UID 응답의 첫 번째 UID 바이트만** 비교한 값입니다. UID 전체를 비교하는 인증이 아니므로 다른 태그에서 오인식될 수 있고 7바이트 UID/다른 프레임 형태는 인식되지 않을 수 있습니다.
- 코드는 정적 비교만 하였으며 AVR 컴파일, 실기기 플래시, 모터 테스트는 수행하지 못했습니다.
- 이 ZIP은 NFC 기능 검토 및 수정안입니다. 적용 전 원본을 백업하고 비교하세요.
