# Bluetooth protocol - Stage 5

UART0: 9600 bps, 8N1

## 기존 명령 (그대로 유지)

- `a` 사료 모터 ON
- `b` 사료 모터 OFF
- `c` 물 펌프 ON
- `d` 물 펌프 OFF
- `e` 덮개 닫기
- `f` 덮개 열기
- `g` 덮개 정지
- `h` 약 A 스텝모터 45도
- `i` 약 B 스텝모터 45도
- `j` 주요 설정 초기화
- `k` 자동/수동 토글
- `m` 보충 완료
- `o` 물 목표량 +10g
- `p` 물 목표량 -10g
- `wx65y1z0\n` 기존 즉시 급식 패킷

## Stage 5 생활모드 명령

모든 Stage 5 명령은 마지막에 `\n`을 붙인다.
앱에서는 안전하게 각 줄 사이에 약 200ms 이상 간격을 두고 전송한다.

### 1. 현재 시간 설정

`T083045\n`

- 08시 30분 45초
- RTC를 추가하지 않으므로 전원이 꺼졌다 켜지면 앱이 다시 보내야 한다.

### 2. 예약 전체 삭제/동기화 시작

`R\n`

### 3. 일일 예약 추가

`S0800x65y1z0\n`

- 08:00
- 사료 65g
- 약 A 1개
- 약 B 0개
- 동일 예약이 매일 반복된다.
- 최대 예약 수는 `config.h`의 `MAX_DAILY_SCHEDULES`로 결정한다. 현재 10개.

### 4. 예약 활성화

`E\n`

- 예약 실행을 활성화한다.
- 자동모드도 함께 ON 된다.
- 이후 휴대폰 Bluetooth 연결이 끊겨도 전원만 유지되면 예약이 실행된다.

### 5. 예약 일시 중지

`X\n`

- 예약 급식만 중지한다.
- 자동 급수는 계속 사용할 수 있도록 `start_mode`는 변경하지 않는다.

## 앱 연결 시 권장 동기화 순서

1. `T<HHMMSS>\n`
2. `R\n`
3. 각 예약마다 `S<HHMM>x<food>y<A>z<B>\n`
4. `E\n`

예:

```text
T073012
R
S0800x65y1z0
S1400x60y0z1
S2000x65y1z1
E
```

## 장치 -> 앱 상태 패킷

기존 `D...` 18자리 형식은 변경하지 않았다. 따라서 Stage 4 Android 앱도 기존 상태 수신 기능을 그대로 사용할 수 있다.

## Stage 10 - 생활 급식 실행 이벤트 / 재조회

생활 예약이 실제로 실행되면 ATmega가 다음 이벤트를 보낸다.

`!L,12,0800,65,1,0\n`

- `12`: 전원 세션 내 실행 순번
- `0800`: 실행 예약 시각
- `65`: 사료 배출 설정량(g)
- `1`: 약 A 개수
- `0`: 약 B 개수

최근 10건은 ATmega RAM에 보관한다. Bluetooth가 끊긴 상태에서 실행되었더라도 장치 전원이 유지되는 동안에는 앱 재연결 후 아래 명령으로 다시 받을 수 있다.

`Q\n`

앱은 연결 직후 `Q\n`을 먼저 보내 실행 기록을 회수하고, 그 다음 현재 시간과 예약을 다시 동기화한다.

주의: RTC/비휘발성 저장장치를 추가하지 않았으므로 ATmega 전원이 꺼지면 내부 시간과 RAM 실행 기록은 사라진다.
